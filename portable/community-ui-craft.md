## 核心流程

# Community UI Craft · 社区资源驱动的界面设计

用真实的公共组件、素材和示例构建完整界面。交付标准是可读、好看、可操作、来源可追溯；不是依赖数量或特效数量。遵循用户当前的产品、技术栈、配色、交付形式和授权范围。本技能不依赖特定 AI 品牌、MCP、订阅或旧项目目录。

## 默认设计约定：先决定表现强度

本技能采用明确的展示型设计预设：**新建展示型网站时，提供鲜明的美术编排、可感知的文字与画面动效、可探索的内容，并实际复用公共视觉组件。** 只有主题、“自行发挥”或“做个网站看看”时，这项预设仍有效，不需要用户每次重说。不能把自由发挥解释为允许省略这些表现；用户明确指定其他风格时以其要求为准。

该展示型预设还包括：**常见图标和操作控件用公开资源及完整组件；展示页各主要章节不以大块纯色充当最终背景，优先使用可感知的动态/交互背景；关键操作采用有质感的弹性按压与回弹。** 图标来自社区只是起点，还要检查实际字重、按钮形态和动作质感。具体选型与验收读 [图标、按钮触感与连续背景](#controls)。

**展示型页面默认启用动效，不自行添加“开启动效 / 暂停动效 / 性能模式”等全局开关。** 默认响应访问者的系统减少动效、后台标签与离屏状态；用户明确要求本地预览完整动效时按“自主完成与自检”统一处理，不修改系统设置。这些生命周期处理不需要占据页面控件。动效必须在正常观看中明显成立，不能仅以背景在运行或组件已导入为依据。

- **表现型展示**：主题体验、艺术/作品展示、品牌官网、活动与产品发布。默认读取并执行 [表现型页面配方](#showcase)。先选视觉资源和体验机制，再决定空项目的技术方案；不要先选最容易写的静态模板，再以框架不兼容为由舍弃效果。
- **操作/阅读型界面**：后台、工具软件、正文阅读、表单、精确数据分析。以内容密度、清晰状态和操作反馈为主；不套用展示页的动态背景要求。需要提升视觉的局部按任务选用资源。
- 用户明确要静态、极简、低动效、严格品牌规范或局部修改时，以该要求为准；减少动效的用户偏好始终有可读可用的替代。

这是一项有适用范围的默认约定，不是让所有界面长成同一模板。基础 UI 库、动画引擎、照片/字体、特色视觉组件分别承担不同作用；仅使用前三类，不能自动说明表现型展示已经完成。

## 工作流程

### 1. 识别真实任务

先查看已有页面、入口、依赖和资产；修旧界面时优先保留现有交互和用户已认可的部分。判断交付是网站、软件工作台、移动网页、原生应用还是幻灯片。

“做一个 HTML”不自动等于必须单文件，也不自动允许改成 React。用户明确要求单文件、双击打开、离线或指定框架时据此选资源。若未限制，选与现有工程和所需组件最匹配的轻量方案，简短说明即可。没有行业资料时使用明确标注的演示内容，不捏造客户或成绩。

只有主题时，先应用上述默认设计约定，再自行决定受众、内容和视觉方向，简短记录假设后完成。一次用户请求可以包含多次内部预览与修正；“一轮交付”不是写一遍代码便结束，也不应变成请求用户逐屏审核。精确事实、真实账号或高影响操作仍遵循实际授权边界。

### 2. 先排内容和资源，再写视觉代码

为主要区域建立简短映射：`位置 → 用户要做什么 → 候选组件/素材 → 官方来源 → 适配工作 → 验收动作`。表现型页面先确定视觉主角与特色交互，基础控件服务它们；操作型界面先确定基础控件与数据。已有依赖能胜任就优先复用。

优先从资源地图的官方 Demo、组件页和源码中选一个可运行起点。搜索具体到功能，例如“React Bits Ballpit”“ECharts linked axis pointer”“UIkit modal”，而不是只搜“高级科技感网页”。查看真实效果与代码，无法查看时标明判断依据。找到合适候选即推进，不进行无目的的全网收集。

原型可以直接开始，不把“用户必须先批准组件名单”设为通用门槛。先做一个典型区域，验证风格和接口，再继续完成授权范围内的页面。

表现型展示默认执行视觉资源驱动模式：先取得具体背景/文字/内容展示组件、适配的美术素材和真实字体，再写整页。通用动画引擎与轮播库只是基础能力；照片加标题、常规轮播、弹窗与局部 hover 不能代替所要求的特色表现。先按“表现型页面配方”做代表区域，通过视觉检查后再展开整页；不要等功能全部做完才考虑是否缺少设计。

### 3. 分清复用与定制

| 内容 | 默认做法 |
|---|---|
| 按钮、弹窗、菜单、选择器、滑杆、标签、表格行为 | 用平台或成熟组件系统，统一主题和状态 |
| 动效背景、交互球、卡片光效、标题动画、轮播 | 选现成组件/公开示例，调整参数、触发与性能 |
| 图表、缩放、刷选、关系图布局 | 使用图表库/官方示例，接真实数据与交互状态 |
| 品牌标识、芯片/产品示意、图标、字体、纹理、模型、图片 | 取得官方/可授权的真实资产；记录具体文件来源，禁止用文字/CSS/SVG 临摹现成品牌资产 |
| 信息架构、页面布局、品牌主题、文案、业务状态、数据适配 | 必须按用户任务设计和编写整合代码 |
| 现成资源无法覆盖的专属插画/模型/行为 | 先查替代资源；仅用户明确要求专属创作时制作原创视觉，否则简化非必要装饰或如实报告缺口 |

用户要求“用现成轮子”时，不要先手写一套看似相同的 shader、弹窗、拖拽库或图表再贴上社区名字。允许主题样式、布局和连接代码：这些是把轮子变成产品所必需的工作。CSS 布局无需为每一个容器再下载组件。

**交付前做来源覆盖检查。** 每个显著的标识、装饰图形、视觉效果、操作控件都应能对应到实际使用的资产或完整组件文件。只写“基于 Motion / Three.js / Radix”不能为新画的 Logo、芯片、发光框或自写动画背书；通用引擎上的自写效果仍是自写。品牌色、排版、组件参数、语义状态和适配代码可定制，视觉内核与现成图形不能以“主题适配”为由重造。发现无来源的替代品，应换成真实资源后再交付，不能只在最终报告承认自行拼制便算完成。

常见返回/关闭/导航图标直接取官方包或 SVG，不用字符、CSS 边框或自己写的 path 拼替代品。选完整样式和状态的控件，而非取一个图标后手写薄圆圈就称为用了按钮组件。公开 SVG 本身也是代码；按来源和最终效果判断，不能看到线条就断言是手画。

使用公共素材的要求也适用于页面里的作品内容：需要大幅作品图时，应取得可授权的具体图像/模型/视频或用户资产，不能未经搜索就把所有作品替换成自己画的圆环和渐变。用户明确要求的专属自绘内容可以补充，但必须如实标注，不把它算作社区素材复用。

### 4. 取得真实资源并接上真实状态

从官方组件页到对应 package、registry 或源码文件。核对版本、样式、必需依赖和许可；保存准确来源。项目依赖安装到项目，不能假设全局 npm 包可直接 import。只引用官网不算实际使用，下载了但未挂载也不算。

普通 UI 控件优先一个完整体系，特色组件可跨库选择，但统一字体、色彩、圆角和间距。不要为一个装饰效果迁移整个已有框架。React、Vue、原生 JS、原生移动控件分别接入，不将 JSX 或 WebGL 图片当成通用即插即用文件。

所有显著操作都应有结果：筛选更新记录；图例控制系列；按钮导航、展开或执行明确动作；内容画廊默认由用户切换，不擅自自动切走信息；展示软件有可进入的演示或诚实的状态说明。视频等内容本身需要的播放控制与全局装饰动效开关不同。无后端时清楚区分本地演示与真实提交。

### 5. 让组件组成一个界面

定义紧凑的视觉约定：颜色角色、标题/正文/数字字体、间距、主要布局、动作节奏。先做主图/真实截图/产品内容，再分配装饰。用户要丰富动效时增加不同层次的反馈：入场、切换、悬停、拖动、数据联动，而非让所有区域同时循环闪动。

同一屏只保留清楚的主次关系。可以有鲜明的视觉主角，其余区域服务阅读与操作。不要把每一句话塞进等大的白框；也不要把“不要白框”误解为整页没有分区。根据内容选择列表、图文交错、全宽作品、工具栏、媒体列表或对比视图。

每个动画有触发条件、作用对象、结束/暂停条件、触屏替代和减少动效方案。离页/离屏停止持续任务。数据、地图、视频和精密点击区域保持稳定，避免整块倾斜缩放。

### 6. 在浏览器中验证并交付

构建通过只证明能编译。实际打开页面检查内容、图片、字体和典型交互，查看宽屏、小窗口和适用的窄屏。对照真实截图修正字号、留白、嵌套边框和视觉重点。没有浏览器工具时说明未实测，不伪造截图、性能或验收结果。

分别验收功能和视觉要求。请求有动效时，实际滚动、移动指针、切换作品观察变化，静态截图不能证明动画存在。请求社区视觉资源时，逐项核对具体组件/素材在首屏和内容区的可见结果；基础依赖数量、无报错和无溢出不能代替这个检查。对照用户批评修正成品，不用“克制”“留白”替代用户明确要求的丰富效果。

交付前完成自主复核：首屏、内容区和窄屏实看，至少一条跨组件交互路径，持续动效的可见变化与停止状态。发现缺陷时自己定位、修复并重测相关路径；尤其检查画面是否与当前选中状态一致，而非只读 activeIndex 或标签文本。具体观察与修正方法见“自主完成与自检”。仅在要求已满足、关键交互稳定且无已知视觉阻塞时结束；工具不可用则明确未检项，不把自评分当事实。

按任务交付可运行文件、适合目标系统的打开方式、实际资源清单、已验证事项和限制。离线交付检查新浏览器会话/清缓存后无必需 CDN、远程字体或热链资产。不要把只能本机访问的 localhost 地址当成分享网址。

## 选择边界

- Three.js 管 3D，p5 管创意画布，D3 管数据映射/定制交互，ECharts 管成熟图表；不要求每个项目全用。
- 来源公开不等于素材全免费、可商用或可再分发；按实际组件/资产许可使用。默认选免费且用途适配的资源，付费依赖不能悄悄引入。
- 不把前一个项目的浅蓝配色、演示数据、中文字体子集、桌面路径和特定业务变成通用要求。
- 用户没有要求的后端、部署、训练、第三方账号、工具自启动不由本技能扩展出来。
- 高级感来自内容和组成方式。现成组件提高下限，仍需模型正确理解任务、整合代码和看效果；不承诺所有模型产出完全一致。

| [daisyUI](https://daisyui.com/docs/install/) | 已用 Tailwind 的 HTML、React 等页面；按当前官方插件安装方法取得组件 markup | CSS 组件不自动提供业务行为；检查键盘和状态逻辑 |
| [HyperUI](https://www.hyperui.dev/) | 内容区、商品、导航等布局起点；打开组件，复制 HTML/Tailwind 代码 | 是布局片段，不是自动处理数据、焦点的完整应用 |
| [TanStack Table](https://tanstack.com/table) | 复杂排序、筛选、分页表格；选对应框架 adapter 与官方示例 | Headless 行为，需要渲染和控件外观；不能当成现成主题表格 |
| [Element Plus](https://element-plus.org/en-US/) | Vue 3 管理平台；从官方指南安装，再从组件页取表单、表格、弹窗等示例 | 适合 Vue，不因需要一个动效而迁移到 React |

先检查项目已有组件库。成熟的现有库无需为追求新轮子全部替换。跨库补充特色效果通常可行，同时装两套完整基础 UI 体系容易增加冲突。

React Bits 当前 [LICENSE](https://github.com/DavidHDev/react-bits/blob/main/LICENSE.md) 含 MIT + Commons Clause 条件，不能简称普通 MIT；应用中的使用和组件本身打包再分发要区分。本技能只提供来源与方法，不把其源码收进资源包。GSAP 使用 [官方许可](https://gsap.com/community/standard-license/)，也不要写成 MIT。

常用检索组合：背景搜 React Bits Silk / ColorBends；卡片搜 GlareHover / Magic Card / Border Beam；标题搜 GSAP SplitText lines mask；交互球搜 React Bits Ballpit；页面过渡搜 Codrops page transition Demo Code。比较实际代码与运行效果，不把 Showcase 当组件下载站。

可直接定位的具体入口（按题材选择，不要求全部使用）：[ColorBends](https://reactbits.dev/backgrounds/color-bends)、[BlurText](https://reactbits.dev/text-animations/blur-text)、[GlareHover](https://reactbits.dev/animations/glare-hover)、[Magnet](https://reactbits.dev/animations/magnet)。React Bits 官方仓库的 `src/content/` 是已使用过的 JS/CSS 来源；例如 `Backgrounds/ColorBends/`、`TextAnimations/BlurText/`、`Animations/GlareHover/`。使用前确认当前路径与依赖，保留同目录 CSS 和仓库许可；这提供下载定位，不固定每个项目的视觉方案。

## 6. 真正的原生软件入口

## 获取与接入

# 获取与接入：从社区 Demo 到项目里的真实组件

## 先建立一个可验证的资源条目

对真正采用的资源记录：名称、具体组件/示例 URL、版本或 commit、许可 URL/文件、取得方式、依赖、使用位置、本地代码/资产路径、修改说明。工程中可建立 `RESOURCE-SOURCES.md` 或使用本技能模板；小页面用几行表格即可，不为了过程文档停下实现。

状态区分：`candidate` 候选、`acquired` 已取得、`integrated` 已挂载、`verified` 已在页面验证。只有后两者能出现在“实际使用”的交付清单。许可证文件与本项目复制的源码一同保留；第三方示例数据换成任务数据。

另分清资源角色：Vite 是构建工具，GSAP/Motion 是动效引擎，Swiper 是轮播组件，ColorBends 等是具体视觉组件，照片/纹理/字体是素材。记录前两类不等于已复用后几类。用户重视视觉组件与美术素材时，来源清单必须覆盖实际采用的这些资源，并标出页面使用位置。

记录 `reuse_class`：`asset` 原始资产、`component` 完整组件、`adaptation` 参数/平台适配、`integration` 布局/业务整合。`upstream_file_or_export` 指向真正用到的文件/导出；视觉内核若有修改，标记 `visual_core_modified` 并说明。全新图形或动画内核不能标成 integration。对动效另记实际触发和肉眼可见结果；无来源的品牌临摹或通用视觉替代品按入口约束替换后交付。

## 四种获取路径

### 1. 官方包

适合 Radix、ECharts、GSAP、Motion、Three.js、p5、Swiper、PhotoSwipe 等。

1. 看现有 package.json/lockfile，选择匹配框架的官方安装指南。
2. 使用项目已有包管理器安装所需包，提交/保留锁文件。安装到项目，不依赖本机全局包。
3. 读取当前组件用法，导入必要 CSS、主题 provider、模块与 addons。
4. 先挂载最小功能，检查真实依赖路径、容器尺寸、事件返回，再适配设计。

例如 Radix Themes 的官方接法包括包、`styles.css` 和 Theme 包裹；缺样式只出现原始按钮不是美化完成。ECharts 必须有有效尺寸的容器，隐藏页初始零尺寸时延后初始化或显示后 resize。

### 2. 组件 Registry / Copy-paste

适合 shadcn、React Bits、Magic UI、Animate UI。

打开具体组件页，确认技术变体、基础库、复制依赖和样式。CLI 命令必须来自该组件页或官方 registry，不能自己拼一个未经核实的地址。检查命令将生成什么文件、是否重置已有主题；安装后看实际 diff，而不是把命令退出成功当成页面已经完成。

手动复制时保留导入项、CSS、依赖和许可。React Bits 的 JS-CSS 与 TS-Tailwind 版本不能随意混搭；组件里使用 OGL 或 Three.js，要安装其实际依赖，而不是“既然有 three 就全能运行”。

推荐将取得的特色组件放 `src/vendor/<source>/`，用薄适配层连接业务状态和设计 token。上游原件与修改可以分开记录，不需要复制整个仓库到应用目录。

### 3. 教程 / 官方示例源码

适合 Codrops、D3 Gallery、Three.js、p5、ECharts examples。

先追踪 Demo→Code→作者源文件，读取依赖、入口和资产清单。记录具体 commit/tag，取得必要子目录；不要只下载入口 JS 却漏掉 shader、模型、HDR、字体或 CSS。与原示例使用的库版本匹配后再改动，避免下载旧例子又盲装最新运行库。

示例搬入项目要拆出 `mount(host, data, options)` / `update(data)` / `destroy()` 等适配职责，或使用当前框架生命周期。算法/渲染可以复用，演示数据、页面导航和全局样式通常必须换成产品内容。

D3 Observable 特别处理：`viewof`、单元格依赖和 FileAttachment 属于 notebook 环境；导出/转为普通模块的本地数据读取与事件更新，不能把 notebook 文本直接放到 script 里。

### 4. 图片、字体、模型与纹理文件

在资产详情页核对内容与许可后下载，通过真实尺寸/MIME/预览验证文件不是错误页。保存来源和作者、压缩适当尺寸，设置宽高/比例，做好加载失败替代。网页运行时不依赖临时下载链接、搜索缩略图或需要登录的链接。

字体同时保留许可；只选择必要字重。中文按当前产品文本生成子集或用覆盖足够的完整字库，动态用户输入保留系统回退。模型检查 glTF 的外置贴图、缩放与朝向；不要把 3D 渲染风格 PNG 当成可旋转模型。

### 下载失败时的自主替代路径

区分“元数据可读”与“文件已取得”。API 返回了图片编号/许可，不等于图像端点可访问。为请求设置合理超时（如 20–30 秒），临时失败可有限重试；同一端点持续 403、TLS 错误或超时就换路径，不反复更换下载器耗尽整轮。

1. 组件网站的 Code/registry 不可达时，沿官方链接进入源仓库，从确切文件路径取得完整源码、样式与许可；API 限流时可用仓库文件页/Raw 或官方 npm 包。未拿到 commit 时记录实际分支、日期与原文件哈希，不捏造提交号。
2. 字体优先官方仓库具体 family 目录中的文件与 OFL；不必等待一个整站 ZIP。检查中文实际字形与所需字重，不因西文下载成功便略过中文。
3. 美术源站失败，寻找同一作品的合法公开来源，或换为同主题的可取得资产。核对作者、版本与许可，不能把替代图片套上旧标题。已获授权的本地素材原件可以复用，记录为缓存取得；不把复制其他项目的页面当成独立创作。
4. 主视觉缺失时缩小内容范围或选择另一条可实现的同主题方案。没有合适公共素材而用户允许生成时才用生成工具，并准确标识。不得静默退回全页几何占位后宣称素材要求已满足。

资源小样应覆盖首屏和一个代表性内容区；先取得这些核心资产，再并行补次要文件与页面实现。不要让所有下载在同一个“全部成功才写清单”的事务里：逐个验证并记录成功文件，失败项不会抹掉已经完成的来源记录。

## 技术栈适配表

| 当前项目 | 优先接法 | 典型误用 |
|---|---|---|
| React | 当前 UI 库 + 对应 React 动效组件，hooks 清理生命周期 | 每次 render 重建 WebGL/图表；CSS/Tailwind 变体混用 |
| Vue/Svelte | 官方对应版本或原生 JS mount/unmount | 粘贴 React JSX 并假设浏览器能执行 |
| 原生 HTML/JS | UIkit/原生语义控件、GSAP/Motion JS、ECharts、Swiper 等 | 为一个文字效果换成完整 React 工程 |
| HTML 幻灯片 | Reveal 当前页/fragment 事件，局部实例 | 用 window scroll 判断下一张幻灯片；清空前后 DOM 却期待 Auto-Animate |
| Electron/Tauri 的 Web UI | 复用宿主框架控件，测试窗口尺寸与本地协议 | 当成普通浏览器而忽略权限、协议、拖拽区域 |
| SwiftUI/Compose/Qt 等原生界面 | 保留平台控件与官方主题，借鉴网页视觉及交互结构 | 宣称网页 CSS/React 组件能直接变成原生控件 |

单文件 HTML：用户明确要求时选择可内联/本地打包的运行库与资源，保留许可。构建阶段使用 npm 不等于交付必须有 node_modules。模块、fetch、WebGL 资产可能受 file:// 限制，需要对双击方式实测；不能满足时说明一个本地启动器的必要性，而非暗改交付要求。

## 适配细节，避免“组件已经装了但效果不对”

- CSS scope：移除或限定示例里的 `body`、`*`、全屏 absolute、全局字体、全局 cursor。主题覆盖放在明确层，少用无止境 `!important`。
- 状态：受控组件接已有选择值/事件，不能另造一份与列表或图表不同步的状态。
- 指针：装饰 canvas 通常不拦截正文点击；可交互 canvas 限在指定区域，区分滚动与拖动；触屏提供点击/按钮替代悬停。
- 层级：tooltip/dialog 的 portal、z-index、边界与滚动定位实际检查，避免卡片 `overflow:hidden` 裁断提示。
- 资源生命周期：清理 RAF、timer、observer、图表、纹理、几何体和 renderer；根据框架选择 dispose/remove/revert。
- 版本迁移：先跑通原件，再局部改动。新增包不是恢复无关旧项目或改变系统自启动的理由。
- 网络不可用：复用已取得的许可资源；没有组件源码时明确缺失，不伪称“使用了 React Bits”。

## 免费、授权与来源

在项目内使用公开组件与把组件源码重新包装成可销售/可再分发的组件库是不同用途。库、示例代码、示例照片、模型、字体的许可也可能不同。按具体资源处理，不把“GitHub 可见”视为授权。默认选择无需账户/费用即可取得且适合用途的资源；不为普通下载额外制造审批流程。

最终来源记录示例（示意字段，不是可原样宣称已验证的成果）：`hero-background / React Bits Silk / 具体组件页 / 固定commit / src/vendor/... / 蓝色与速度参数适配 / 品牌页首屏 / 实测宽屏与减少动效`。实际版本、路径、许可文件必须从本次项目取得。

## 组合与动效

# 组合与动效：把现成组件组织成一个产品

## 首先回答每一屏的任务

官网让人理解公司与产品并进入体验；工作台让人查看数据并完成操作；汇报让听众理解论点与证据。主图、字体、交互强度和信息密度由任务决定。不要给这三种产品套同一种首页模板。

先写简短视觉约定即可开工：

- 颜色角色：背景、内容面、正文、弱文本、主操作、状态色；用户指定蓝白则围绕蓝白做层次，而非机械改成黑金“高级感”。
- 字体角色：标题、正文、数字/参数、图注；中文、英文、数字分别检查。正文通常以清晰无衬线为主，衬线/装饰字体限合适标题。
- 表面角色：背景承载气氛，主内容承载阅读，控件承载操作，强调色承载选择；不让四者都变成同一浅色卡片。
- 布局角色：首屏主角、内容节奏、主要动作和信息顺序；先明确主图/产品预览在哪里。
- 动作角色：哪些是一次性入场、哪些由用户触发、哪些确需持续运行。

本技能的展示型预设还包括连续的背景层次和有弹性的操作触感。主要章节不以大块纯色作为最终背景；先按入口中的“图标、按钮触感与连续背景”选择完整控件与背景方案，再围绕内容调节。局部阅读底面和减少动效替代保留可用性。

## 五种常见不足与正确修法

| 看到的问题 | 应改什么 | 不足以解决问题的做法 |
|---|---|---|
| 满屏白框、像模板 | 用图文交错、全宽作品、编辑式列表、真实软件预览、不同内容比例形成节奏 | 给每个框再加彩色发光边 |
| 字体单调 | 改标题/正文/数字角色、字重和行长，核对中文字体是否真加载 | 装五套西文字体而中文一直走系统回退 |
| 大块纯色、内容空 | 加真实图片、产品截图、作品预览；背景材质有层次，文字区稳定 | 每屏换一个毫无关系的渐变 |
| 只有首屏球会动 | 为切换、展开、列表、数据选择增加连续反馈 | 所有组件同时自动循环 |
| 图表不互动 | 增加真实选择、范围控制、提示、图例、明细联动 | 数字来回跳或无限闪光 |

空白不总是问题。先看内容是否有明确主次；低密度品牌页需要留白，数据工作台则优先可扫描的信息与有效空间。避免为填满屏幕编造无意义指标。

## 视觉资源驱动模式：表现型展示的默认路线

此模式由入口的任务分类决定；只给主题的表现型页面也适用，不需要用户重复说“丰富动效”。这里的“艺术感”不自动等于纸色底、系统宋体、大留白和自绘圆环。“动效丰富”也不能只交付全站淡入加轮播。按表现型页面配方先形成体验机制并选取真实资源，不把克制当作省略需求的理由。

在整页开发前做一个资源小样，直接挂载计划使用的组件、字体与作品图。它可以成为最终首屏，不是额外等待批准的步骤。先验证这些资源组合起来的效果，再围绕它组织长页。

| 视觉任务 | 从哪里取得什么 | 必须看到的结果 |
|---|---|---|
| 有层次的主视觉 | React Bits 的 ColorBends、Silk 等具体组件；或 Codrops 具体公开 Demo 的效果代码 | 背景有可感知的动态/指针反馈；在自身阅读区域控制对比度，有静态替代 |
| 有性格的文字 | Google Fonts / Noto 官方字体文件，搭配 BlurText、RotatingText、SplitText 等适用文字能力 | 标题形态、字重、行距经过设计；中文实际使用所选字体，进入/切换时存在有意义的变化 |
| 作品可看、可切换 | 合法取得的具体作品图/摄影/纹理或用户作品；搭配 Swiper、PhotoSwipe、React Bits 展示组件或 Codrops 图片切换示例 | 不同作品有真实视觉差异；切换时图像、标题、说明同步；可拖动/点击且能回退 |
| 局部操作的触感 | GlareHover、Magic Card、Magnet 或其他已核实的公开组件 | 指针或点击反馈在实际页面能观察到，不抢走文字阅读或导致精确点击漂移 |
| 向下浏览的变化 | GSAP ScrollTrigger、Motion 或组件自带滚动能力 | 作品与文字随章节呈现、构图产生变化，不能每节都是相同位移淡入 |

这是资源与任务的映射，不要求同一网站装满这些库，但表现型配方中的可见角色需要覆盖。选择一个连续的艺术方向，把不同资源统一在它里面。避免从一个单调模板跳到另一套默认霓虹模板。

### 下载并使用美术内容

从资源地图进入具体资产页，选有明确来源和可用许可的图像、纹理、模型。保存实际文件、作者与链接。展览中借用公开艺术/摄影，应称为“视觉参考/选集”并提供来源，不把别人的作品写成虚构工作室的真实客户案例。没有客户资料不意味着只能画占位 SVG。

用户明确要求专属创作时，可绘制独有图解或生成专属素材并如实标识；默认严格复用的任务中，缺资源应先选兼容替代，不自行画一个占位品作为成品。生成素材也不能冒充下载的社区作品。

### 排版不能停在 font-family 声明

取得确实允许使用的字体文件和许可。中文可用 Noto Sans/Serif SC 等覆盖足够的字库，再选与主题匹配的拉丁展示字；并非每次都要衬线。字体子集应包含当前文案，动态内容有回退。用浏览器确认字体已加载，尤其防止英文换了字体而中文仍全部落到系统默认。

从题材选择形态、比例和断行：标题可以成为构图本身，正文仍清晰。需要文字动效时选现成文字组件、配置触发与终态，不能把大字或换一种颜色称为动画。

### 验收时问具体问题

- 首屏所选社区视觉组件在何处？其纹理、光线、深度或指针响应是否真的出现？
- 哪些图片和字体是本次取得的？资产清单与页面实际内容是否一致？
- 向下浏览后是否出现新的内容形态，而不是相同白框或纯色段落？
- 文字动画与作品切换是否实际运行？减少动效模式是否仍保留完整内容？
- 用户要的效果强度是否达到了？功能通过与视觉达标应分别描述。

## 组件混搭的统一方法

用一套基础控件定义按钮高度、字体、焦点和状态；特色组件进入同一设计语言。主题尽量通过组件 props、CSS variables 和 scoped class 适配，保留上游行为。

例：Radix 管按钮和标签，React Bits Silk 管首屏材质，BlurText 管一句标题，Swiper 管作品浏览，ECharts 管数据体验。它们可以同时存在，但统一文字、对齐和主蓝；内容页不因此必须都变成透明玻璃。

决定一个容器的依据是它是否表达独立任务或状态，而非有没有 Card 组件。页面标题、正文段落、论文图和长列表可以直接放在布局中。控件、悬浮预览、独立功能可以有边界，半透明只用于合适的层级。

展示软件时优先真实截图/实时预览和可进入的演示。只有外框和假折线的“电脑模型”不能代替软件内容。项目图、行业图、产品图服务不同任务，避免全部用同一张科技纹理。

## 动效配方与触发

以下为起始建议，不是所有项目的硬性数值要求；品牌、触屏和用户偏好优先。

| 作用 | 优先现成能力 | 编排原则 |
|---|---|---|
| 背景气氛 | Silk/ColorBends/合适的公开 WebGL 效果 | 慢变化、低对比，标题清晰；静态 fallback；可见时运行 |
| 首屏标题 | BlurText 或 GSAP SplitText | 按词/行编排，约半秒级完成；先预留布局，不反复消失 |
| 短语切换 | RotatingText / Word Rotate | 只用于补充词；保留完整静态句子，考虑读屏与可关闭 |
| 主按钮 | Animate UI 完整 Button/FlipButton、适配的 Uiverse 作者按钮 | 按任务选择真实的按压与弹性反馈；hover、focus、disabled 都清楚；不只用图标加自画外框 |
| 精选卡片 | GlareHover / Magic Card / Border Beam | 限重点卡片；内容本身可读，触屏不依赖鼠标效果 |
| 面板与列表切换 | Motion layout/AnimatePresence 或 Animate UI | 保持空间连续性；约150–300ms起步；不重新加载内容 |
| 作品切换 | Swiper 或选定 Codrops 示例 | 当前项、前后切换、触屏手势和暂停都有效 |
| 数据更新 | ECharts setOption / D3 update join | 呈现真实状态变更，约300–650ms起步；不同指标量纲变化有明确提示 |
| 讲解路径 | Reveal fragments + GSAP DrawSVG | 随讲解推进，前进/后退可重现；不是自动播完所有内容 |

不同时把 Motion、GSAP、CSS animation 放到同一节点的 transform；可分层容器或统一一个动画拥有者。高频渲染不要随 React 每次 render 重建。

## 性能与可访问性是视觉质量的一部分

持续动效默认启用，不默认提供页面动效开关。后台/离屏自动停止，系统减少 motion 时静态呈现并响应偏好变化；只有用户明确要求才增加页面开关。不要为演示引擎状态添加悬浮播放/暂停控件。

WebGL 画布数量和分辨率按设备能力控制，先观察帧率/卡顿，再做降级。普通品牌区通常不需要多个全屏 canvas 同时渲染。对大面积 blur、box-shadow、后处理和高分辨率纹理实际测量，不能仅凭“transform很快”宣称性能良好。

不要整体倾斜图表、地图、视频、表格或精确操作面板。它们的定位和阅读比跟手光效重要。装饰层不遮挡点击，触屏提供等效动作；弹窗有焦点恢复，输入和选择器可以键盘操作，轮播不绑架页面滚动。

字体异步加载前后、标题动画前后、图片加载前后不应跳动；固定图像比例，给替换文字留合理空间。图注/坐标不能因缩放整页变成几像素。

## 看成品再改，不靠组件清单自评

在实际渲染结果中找主角是否明确、文本是否足够大、内容是否真实、按钮是否产生结果、图表是否解释数据。看一屏和整页节奏；再看小窗口和触屏。发现问题时回到布局、内容和状态，不默认再加一个库。

借鉴案例的可迁移经验：官网成功在于真实产品预览与特色组件结合；软件工作台成功在于字号、工具栏、媒体缩略图和状态统一；论文汇报的问题常在缩小画布、重复左右栏、八宫格流程。吸取方法，不复制业务数据或私人资产。

## 表现型页面配方

# 表现型页面：把社区视觉能力变成一次完整体验

适用于主题体验、艺术/作品展示、品牌官网、活动与发布页；只给主题时也适用。操作型软件、长文阅读、用户明确的静态/低动效要求不套用本节。这里要求可见的表现，不规定所有页面同色、同构图或同组件。

## 1. 先写体验机制，避免从普通模板起步

用一句话说清：**用户做什么 → 画面中的什么发生变化 → 因此理解/发现什么。** 例如“拖动浏览一组展品，主图、标题和细节随当前展品一起切换”；“向下穿过若干环境，素材尺度、章节文字和空间关系随之变化”。这比“高级、自然、神秘、杂志风”更能指导选择。主题应体现在可操作的组织方式中，不只是站名、颜色、英文小字或坐标装饰。

从主题提炼美术线索，再挑资源。自然题材不必总用雾林照片，艺术题材不必总用米色和宋体，科技题材不必总用蓝色球。摄影可以成为主角，但需编排成画面关系与发现过程；不能以摄影天然好看为由省略动态和内容互动。

先搭一个最终页面可复用的代表区域，包含主视觉、实际中文标题和一次内容操作。**先看它，再扩页。** 如果仍像“普通背景照片＋居左大标题＋矩形按钮”，应改变构图/视觉机制，而非加一个底部光标动画后继续交付。

## 2. 必须覆盖的可见角色

这是表现型默认验收，不是库数量配额。一个组件可以承担多个角色，但每个角色须有实际画面依据。

| 角色 | 应实现什么 | 不足以替代的东西 |
|---|---|---|
| 环境/主视觉 | 具体公共视觉组件或公开示例，让画面有空间、材质或可感知的时间/指针/滚动变化；背景语言延续至主要内容区和结尾 | 单张背景照片、整屏纯色、隐藏 canvas、只有首屏背景会动 |
| 字形与文字表现 | 真正加载的适配字体；标题形态、断行、比例参与构图；至少一处来自成熟文字组件/公开示例的编排，与进入或章节切换关联 | 仅增大字号、英文用特色字而中文不变、所有段落同一种淡入 |
| 内容探索 | 作品/场景/产品有真实视觉差异；至少一种有设计的切换、揭示、缩放或空间浏览，让图像与信息一起响应 | 所有按钮打开同一段文字；只有下划线换位置；普通默认轮播单独承担整站设计 |
| 滚动节奏与触感 | 首屏之后仍有视觉事件；章节在图像尺度、布局、材质或动作上有变化，现成控件提供与任务相称的弹性反馈 | 第一屏有特效，以下全是纯色左右图文；图标加薄外框代替完整组件；所有区块同时晃动 |

常规弹窗、导航、按钮当然应复用。记录来源时区分 `基础控件`、`运行/动画引擎`、`特色视觉组件/具体示例`、`美术资产`。UIkit Dialog、Swiper 核心、GSAP 包、照片分别有价值，但不能统称为已经实现了四种视觉效果。

四种角色要在实际内容中成立：正常进入即有动作；向下浏览，主要章节仍有文字揭示、影像响应或内容转场；选择/指针操作有对应反馈。共享淡背景加首屏 BlurText 不足以覆盖长页。取得具体公开组件/示例后，在记录中写明各章节的触发和可见结果；不要自行写一套动画再把引擎名称当成组件来源。默认不添加全局动效开关。

减少动效/低性能替代保留主图、独特构图和所有内容；不是删除作品，只留下大块纯色。默认正常模式和静态替代分别检查。

内容承诺也属于设计：编号/页码须对应实际可切换内容；“阅读故事”应打开故事，而不是换个名字显示同一份档案；阅读时长、数量和进度应有依据。不要用虚构计数和英文标签填补内容的空洞。

## 3. 选一条资源路线，做成自己的设计

以下是起点，不是固定站点模板。现有项目保留技术栈；空项目允许根据选中的组件选择 React 等框架。“网页/HTML”本身不禁止构建工具，明确“原生单文件”才是约束。

### A. 材质与光影驱动

适合抽象艺术、创意品牌、数字展览、具有流动感的发布页。

- 主视觉：从 [React Bits ColorBends](https://reactbits.dev/backgrounds/color-bends) 或 Silk 中选合适材质，真实下载代码与样式。依照素材色调重新配色，控制阅读区亮度；不要照搬组件站的默认彩虹。
- 文字：[BlurText](https://reactbits.dev/text-animations/blur-text) 配合真实字体；首屏、章节转场或当前作品标题选择适合的触发，不必每句都动画。
- 内容：具体授权作品图与 Swiper/PhotoSwipe，或选更有空间感的 [CircularGallery](https://reactbits.dev/components/circular-gallery)。画廊是探索入口，说明文字和详情仍需可读 DOM。
- 触感：GlareHover/Magnet 只用于适合的重点区域。光效应强化材质，不把所有矩形变成发光卡片。

背景延续、图标字重与整套按钮的具体取得方法见入口所链接的“图标、按钮触感与连续背景”。不将首屏用上两个社区组件视作整页已经完成。

### B. 影像与空间驱动

适合环境叙事、摄影展、旅行想象、建筑与设计作品。先给图片安排主景、细节、过渡、信息载体等不同角色，再选切换方法。

- 影像过渡可从 Codrops [Creative WebGL Image Transitions](https://tympanus.net/codrops/2019/11/05/creative-webgl-image-transitions/) → [作者源码](https://github.com/akella/webGLImageTransitions) 选择一个实际效果；或从 [SlideshowAnimations](https://github.com/codrops/SlideshowAnimations) 选与现有栈兼容的方案。旧示例先跑通其依赖，不混装不兼容的新版 Three.js；示例照片/字体许可单独核对并换成选定资产。
- 文字配合 [React Bits SplitText](https://reactbits.dev/text-animations/split-text) 或 GSAP 官方 SplitText 示例的行/字编排，形成揭示节奏。
- 环境层可用适配的公开视觉组件、图像视差/遮罩示例或公开 3D 例子。以内容与空间呼应为准；不要求在景观上硬叠无关的抽象球。
- 选择一段把整幅环境转成局部细节或可浏览档案；让“进入/探索”确实改变体验。不要只把全页图片做得更暗。

### C. 结构与数据驱动

适合软件产品展示、数据故事、科技品牌。以可操作产品/数据为主角，公共视觉组件营造气氛。

- 背景可选 [RippleGrid](https://reactbits.dev/backgrounds/ripple-grid) 一类有指针响应的具体组件，或 Three.js 官方示例。按产品含义调成网格、测量或空间线索，控制对比度。
- 主内容接真实可用的软件预览或 ECharts/D3 官方示例，再联动筛选、精确值与说明；没有真实业务时明确标注样例。
- 文字强调状态/章节，切换时解释前后变化；动效不能让虚构数字冒充测量结果。

如果首选资源不兼容或下载失败，换同角色的可用公开方案；不要不作说明地把整个表现型方案降成静态照片模板。仍无法实现时如实报告缺失角色。

## 4. 从页面链接走到实际挂载

资源页 → 对应源码/registry → imports 与依赖 → 同目录样式 → 最小真实尺寸容器 → 实际素材 → 主题适配 → 浏览器实看。记录具体上游路径、版本/提交与许可。以下定位在整理时核过，后续以当前上游为准：

| 组件 | 官方 JS/CSS 源码位置 | 接入时容易漏的事 |
|---|---|---|

主题适配和状态连接允许自己写：这不是重造轮子。动画内核、复杂拖拽、图表布局、shader 的已有实现优先复用。保留许可，按项目本身的条件判断使用与分发；不要把此技能包变成第三方源码再分发包。

## 5. 两次有目的的视觉检查

**代表区域阶段：** 正常比例查看主视觉、真实中文和内容切换。问“如果拿掉标题，这段是否仍有主题线索”“画面变化是否肉眼可见”“主视觉是否只是模板照片”。不成立就先换资源/构图/交互方法，别靠之后多写三屏文案补救。

**整页完成阶段：** 以用户方式进入、移动指针、向下滚动、选择内容、打开并返回，再看适用窄屏。指出整页最普通/重复的一段；若仍是连续同底色图文、重复主图、无意义小字或只有首屏动效，修它。保留做得好的部分，不重新随机换一套配色。

视觉验收应记录实际观察，例如“指针横移时材质光带位置改变”“选择另一件后主图与标题共同转场，详情对应当前件”。`已导入组件 / 无报错 / 图片加载 / 按钮能点 / 自评分高` 均不能单独证明设计完成。

一个常见失败组合是：照片＋大宋体标题＋米色图文段落＋基础轮播＋弹窗。它可做正常内容页，却不足以完成本模式的表现要求。补救重点是让素材、排版与动作形成主题体验；只添加星点、光标或更多装饰标签仍然不足。

## 图标、按钮触感与连续背景

# 图标、按钮触感与连续背景

适用：采用本技能设计预设的社区组件 UI，以及“像临时拼出来的、图标粗糙、背景单调、想要果冻感”等修订。这里把审美反馈转成可执行的选型和验收，不宣称能客观识别一页是否由 AI 制作。遵循用户当前品牌和平台要求；展示背景的约定不等于让阅读文字、输入框或精密图表不停运动。

## 1. 控件按完整成品选择，不能只下载一个图标

常见导航、返回、关闭、收藏、菜单、播放等符号直接用公开图标包/官方 SVG。不要用 Unicode 箭头、两个 div、旋转边框、临时 SVG path 或 canvas 自画替代已有图标。没有匹配项时继续查同体系或相容的资源；业务状态、布局和主题适配仍需要自行编写。

先选择图标体系，再选择承载它的完整按钮：尺寸、形态、底面、内边距、对比度、焦点、按压和禁用状态。精致不等于越细越好；正常显示尺寸下检查是否过细、过小、偏心或像两根临时线段。优先比较 regular/bold/fill/duotone 等实际预览，不将某一种图标字重规定为所有页面的答案。

图标和操作语义对应：返回上一层、回首页、上一项、下一项、外链是不同动作。不能全站都用斜向箭头。图标按钮要有可读名称，文字按钮的图标是补充；装饰图标不占用多余读屏焦点。一个界面保持一致的视觉重量，不能随手混用极细 outline 和厚重 fill。

| 公开资源 | 去哪里取 | 怎么用与适用场景 |
|---|---|---|
| Phosphor | [官方图标目录](https://phosphoricons.com/) · [React 包与文档](https://github.com/phosphor-icons/react) | 从同一套图标选返回/方向/收藏等；React 使用 `@phosphor-icons/react`，按需导入。支持不同 weight；需要更饱满质感时比较 bold、fill、duotone，而不是自己重画轮廓。其他栈选官方对应实现或 SVG |
| Lucide | [官方目录](https://lucide.dev/icons/) | 已有项目可保留；检查组件被缩小、低对比或过度减细描边的问题。不要因它来自社区就免做视觉检查，也不要把所有线性图标认定为粗糙 |
| Animate UI Button | [完整组件](https://animate-ui.com/docs/components/buttons/button) | 有预设样式及 hover/tap 能力。组件页 Installation → CLI/Manual，取得全部依赖、基础原语和主题样式，再替换颜色/文案/图标；只复制 headless primitive 不等于拿到了完整外观 |
| Animate UI Icon Button | [完整组件](https://animate-ui.com/docs/components/buttons/icon) | 适合强调的收藏/图标操作，含点击表现；返回、关闭等高频操作通常更适合普通动效 Button 的 icon 规格，不能因有粒子就处处使用 |
| Animate UI 动态图标 | [安装与示例](https://animate-ui.com/docs/icons/get-started) | 取得所选图标及共享 wrapper，按 hover/tap/view 触发；不对导航图标默认无限循环。按当时版本核对 API |

上表资源各有许可，使用时保留具体版本与许可文件；Phosphor 使用 MIT，2026-09-28 核对的 Animate UI 仓库 LICENSE.md 为 MIT + Commons Clause，不能只凭旧介绍写成无附加条件 MIT，其他依赖也分别核对。图标可以是包、SVG 或官方导出资源，并非必须换成位图才算“素材”。

## 2. 果冻感来自受控的弹性，而非随处晃动

用户要有弹性的动态反馈时，先取现成按钮/交互组件或具体作者示例，不临时自写一套 keyframes 冒充社区实现。选与场景匹配的一种触感：按压缩小并回弹、轻微形变、吸附、切换时柔和展开。普通颜色 hover 或瞬间切换不能独自满足此项。

完整基础按钮加上自写 `whileHover/whileTap` 仅是基础组件上的定制编排，不等同于取得现成动效按钮。此用户默认要求严格复用时，直接取得带动作的完整公开实现，再用其支持的参数适配；同理，不用旋转方框加品牌文字模拟官方芯片图，不用字母加底色模拟品牌 Logo。资源找不到时换兼容资源或省略非必要示意，不凭“简单”绕过来源要求。

- **主要行动按钮：** 可选 [Uiverse / vinodjangid07 的 Jelly Button](https://uiverse.io/vinodjangid07/horrible-husky-70)。进入作者页取完整 HTML、CSS 与许可；对应的 [官方介绍](https://uiverse.io/blog/10-ui-elements-you-can-copy-paste-in-30-seconds) 可帮助定位效果。将样式加作用域，保留按压/回弹的表现，适配品牌色；从真实源码取样式，不照抄网页抽取文本里可能多出的单位空格。该作品页标明 MIT，保留作者说明。
- **常用按钮：** Animate UI 完整 Button 的 hover/tap 动效作为起点。想要回弹时核对其 motion/transition 接口与原语行为，再通过支持的参数调整。不要猜 `jelly`、`bounce` 等不存在的属性，也不要给同一节点叠加两个冲突的动画系统。
- **强调的内容切换：** [Animate UI Flip Button](https://animate-ui.com/docs/components/buttons/flip) 提供弹簧转场能力；选中态、标签或面板可使用 Animate UI 对应 Tabs/Popover。动作应保留当前项与新项的连续关系。
- **指针触感：** [React Bits Magnet](https://reactbits.dev/animations/magnet) 适合少量展示入口。它是磁吸，不是果冻形变；不能只用了 Magnet 就宣称所有控件已有按压回弹。

保留按钮稳定的点击区，视觉层可以轻微变形，文字不应压扁到难读。hover 不是唯一入口，触屏按压与键盘 focus/activate 也有清楚反馈；不靠额外延迟阻止操作。快速反复点击、移出和松开后都要归位，不积累放大或卡在中间态。减少动效时保留清楚的静态状态与完整功能。

用户要求控件有弹性，不等于让整个数据面板、正文、地图跟随鼠标歪斜。装饰和操作有反馈，精确阅读与定位保持稳定。

## 3. 为整页规划连续的背景，而非只照顾首屏

在本技能的表现型展示预设中，**大块米色、黑色、白色或其他纯色均不能作为主要章节的最终背景。** 色值可以作为底色，但上方需要实际可见的公共材质、动态光场、主题媒体或交互层。颜色换一遍、加一粒几乎看不见的噪点不算完成。不要以“极简”重新解释掉该预设；用户明确要求其他风格时，以当前需求为准。

开工时对每个主要章节记录：`公共背景资源 → 可见范围 → 时间/指针/滚动触发 → 内容遮罩 → 离屏/暂停/减少动效处理`。一次规划同一套环境语言，并随章节改变参数、素材或取景；不要每一屏换一个毫无联系的彩虹 Demo。

| 需要的背景质感 | 可用资源路线 | 集成重点 |
|---|---|---|
| 流动材质、织物或雾感 | [React Bits Silk](https://reactbits.dev/backgrounds/silk) | 保留可感知纹理与慢变化；中间内容区可沿用这套环境，通过亮度和局部遮罩调整，而不是直接改成不透明纯色 |
| 可跟随指针的光色 | [ColorBends](https://reactbits.dev/backgrounds/color-bends) 或 [Iridescence](https://reactbits.dev/backgrounds/iridescence) | 取组件与同目录 CSS，核对依赖。前者使用 Three.js，后者当前源码依赖 OGL；各自参数不同，不互相套 props。检查输入是否被覆盖层截走 |
| 光幕与章节过渡 | [Aurora](https://reactbits.dev/backgrounds/aurora) 或已有 Codrops 主题影像示例 | 用同色系和构图形成章节变化，阅读层维持稳定对比；不能因文字遮罩过厚又把所有背景盖成纯色 |
| 连续渐变与较平缓的变化 | [Animate UI Gradient Background](https://animate-ui.com/docs/components/backgrounds/gradient) 的公开组件 | 先查当前依赖与样式，并检查实际运动；它是 React 路线，不能直接粘入原生 HTML。原生限定任务另选兼容的公开示例，不悄悄退回纯色 |

优先共享一个背景层，或只运行视口内的背景实例；不为每一段同时开全屏 WebGL。正常模式默认运行，**不生成全局动效开关、暂停悬浮球或开启特效按钮**。后台标签、离屏和系统减少动效自动处理；用户另有明确要求时才提供页面开关。减少动效、WebGL 不可用时保留有层次的静态纹理/主图，不能降级成内容空洞的纯色块。

正文、表格、输入和局部控件可有稳定的阅读底面；这不是给整屏纯色章节开例外。动态存在于它们周边、底层可见区域或章节过渡中，确保正常比例能感知，又不影响读数和点击。

## 4. 验收来源，也验收质感

- 逐个检查显著的返回/关闭/导航/收藏按钮：具体图标和控件来自哪里，实际大小和字重是否合适，是否只剩极细线条和空外框。
- 在首屏、页面中部、结尾各看一段：背景是否仍有可见层次和要求的运动，是否出现整屏纯色断档；不要仅验证 canvas 数量。
- 悬停 → 按下 → 松开 → 移出，再快速重复并用触屏/键盘操作：能否看到恰当的弹性反馈，并稳定回到可点击终态。
- 查看动画最亮/最暗时刻的文字与控件，不以低透明度掩盖不可读，也不把效果压到不可察觉。
- 查来源记录和页面挂载位置：整套按钮、图标、背景各对应实际组件/示例；布局和状态连接可以定制，但应如实区分。
- 检查品牌资产、产品示意和重点装饰的实际文件，不接受字母 Logo 或 CSS 芯片等临摹替代；无来源项要在交付前替换，不能只列为已知限制。
- 页面默认已有动效且没有擅自添加的动效开关；系统减少动效仍可用。深色遮罩下若看不出背景变化，就视为视觉未通过，不能以两帧像素不同抵扣。

发现“用了公共库仍像临时拼装”时，先换合适的完整控件、图标字重和参数，并统一材质与动作语言。不要只换库名，也不要靠叠加更多无关装饰去遮盖问题。

## 自主完成与自检

# 自主完成与自检：一次需求内完成设计、观察和修正

用于新建完整网站/软件界面、只给主题、自主发挥或一轮交付。局部文字/颜色修正无需套用全流程。这里的一轮是用户只提交一次需求；你自行检索、编写、运行和修正，不依赖另一位设计指导者不断补提示。它不表示单次代码生成，更不保证每个模型产出一致。

## 1. 把简短主题变成可制作的方向

先在自己的工作记录里回答：这是何种界面、面向谁、用户能做什么、什么视觉形象代表主题、页面如何展开。用户允许自由发挥时自己作出选择，不把常规设计决定变成追问。虚构故事或作品集可以写完整示例内容，但不能冒充真实机构业绩。

先应用入口中的表现型/操作阅读型约定，再考虑两个简短方向，按主题适配、素材可取得性、内容可读性和交互价值选一个。表现型方向必须包含具体体验机制：用户动作、画面变化与内容意义；仅说“摄影式编辑档案”“大字和留白”仍不完整。不要长时间列方案或等批准。

明确一个主视觉形象、一种字体性格、一组颜色角色和一条主要操作路径。主题应体现在图像/材质、内容、排版和交互里，不能只出现在页面标题。不要复刻此前示例的名称、相纸布局、配色或组件全家桶。

## 2. 用真实资源验证方向，再展开整页

按任务查资源地图和获取与接入。为关键位置写简短的“位置 → 内容/操作 → 具体资源与来源 → 适配 → 如何看出有效”。通常需要检查这四层，但不要求为每层都安装一个库：

- **视觉主角**：具体图片、模型、视频或公开视觉效果，进入首屏真实渲染。普通业务页面也可由真实产品界面承担主角。
- **文字形态**：取得并加载适合题材的字体，中文/英文分别确定角色；表现型页面实际挂载文字组件/公开编排示例，操作阅读型按任务决定。
- **内容呈现**：作品、项目、章节、数据应有真实差异；选择适合的成熟展示/交互资源，不能全站只有一个会动的背景。
- **操作反馈**：导航、选择、展开、缩放或其他真实状态变化。装饰性鼠标光效不能代替操作。

先让主视觉资源、标题字体、一个代表性内容区实际跑起来并实看。表现型页面按入口链接的配方检查四种可见角色；照片、字体、轮播和弹窗不自动覆盖这些角色。资源与风格不可用就尽早换合适候选，不先写满整页再用占位图硬补。下载失败按获取文档的替代路径处理；替代素材仍须符合主题，不因为手边有一张公司机房照片就塞进无关艺术主题。

公共组件负责成熟行为与特色表现；你负责内容结构、主题样式、比例、状态连接和整体节奏。统一色彩、对齐、文字与运动速度，删除互相抢注意力的效果。不要逐区照搬几个 Demo 的原配色后拼成页面。

## 3. 把设计指导转成可执行的自检

在浏览器按目标尺寸实看首屏、一个核心内容区和整体滚动节奏。局部截图用于读字号、构图、裁切与对比；全页截图看重复结构与章节变化。截图必须被实际查看，保存文件不等于完成设计检查。

| 自己观察到的症状 | 排查与修正动作 | 修好后应看到什么 |
|---|---|---|
| 页面像换了名字的通用模板 | 检查主题是否只有标题；让核心素材、文字形态和主要交互体现主题，改掉重复占位块 | 隐去站名仍能判断大致题材；内容区各有目的 |
| 背景仍像一块纯色 | 检查 canvas 尺寸、层级、shader/依赖错误和静态 fallback；比较不同时刻及指针位置，再调组件参数 | 不看源码也能观察到所承诺的纹理或运动 |
| 光效很强但文字忽明忽暗 | 观察动画不同阶段，优先对阅读区域加遮罩、控制局部亮度/色彩，保留外侧效果 | 最亮阶段文字仍可读，同时动效仍可感知 |
| 字体声明漂亮，中文实际普通 | 核对下载文件、字体加载状态、字形覆盖及 CSS 实际选用；调整中文与拉丁标题角色 | 中文标题真实使用所选字形，正文稳定可读 |
| 字太小、看起来“精致”但费力 | 在正常比例查看，检查主要正文与操作是否普遍缩到 9–11px；普通网页以约 14–18px 正文、13–16px 控件为起点，按场景调整 | 不放大也能读内容和识别操作；小字仅用于次要元信息 |
| 标题末尾只剩一个字或标点 | 根据窄屏实际行宽重排，必要时设置有语义的断行与断点字号，不只是缩小整页 | 标题在宽/窄屏都有完整短语节奏，不溢出或切字 |
| 图很大但并不好看 | 实看素材本身、分辨率、主体位置与裁切；决定何处保全图、何处可裁切，不拉伸 | 主题主体清楚，画面与文字比例有意图 |
| 每一节都是同一排卡片/同一种淡入 | 看全页缩略图，按内容改为全幅图、错位图文、列表、作品浏览或交互工作区；让动作服务不同状态 | 向下滚动出现内容与比例变化，而非堆特效 |
| 有 pointer 回调但没有感知 | 实际移到视觉作用区域；检查覆盖层、pointer-events、事件监听位置、影响半径/幅度和设备类型 | 鼠标动作有适量反馈，点击仍可用；触屏有替代 |
| 作品选中状态正确，画面却错了 | 看当前图像/文案本身与几何位置，检查原生滚动偏移、transform、透明叠层和焦点恢复 | 可见图像、标题、索引、详情均属于当前项，无邻页透字 |

不需要预先实现表中所有修法；它们是看到问题后的定位方法。纯色、留白或系统字体在操作阅读型界面或用户指定风格中可以成立；表现型默认要求不能因此省略。检查整页图像的尺度和用途变化，避免主图未经新编排重复出现；手机端检查阅读节奏，不止检查无溢出。

## 4. 观察运动与终态，别只看一张截图

先让字体、图片和入场完成，再观察：进入页面 → 移动指针 → 滚动章节 → 改变内容选择 → 返回。记录哪个元素发生何种变化。对持续背景在相同视口比较不同时刻，区分时间变化与指针变化；不要用控制台变量改变冒充用户能感受到的效果。

正常模式无需点击开关就有动效。检查后台/离屏自动停止与重新可见后恢复，并模拟系统减少动效，确认完整内容保留；不要为了验收而在成品添加动效开关。仅在用户要求了页面开关时测试其暂停/恢复。只证明有 canvas、RAF 或两帧像素不同不是视觉验收；还应在正常尺寸实际看到预期幅度，截图比较时保持滚动和鼠标条件稳定。

若用户实际页面“完全静止”，先读取该页面的 `prefers-reduced-motion`、`visibilityState`、实际组件版本与触发状态，不能拿独立无头浏览器的结果替代。宿主内嵌浏览器可能与测试浏览器报告不同偏好。用户明确要求看完整动效时，可只对该本地预览设置完整模式，同时让文字组件、WebGL、轮播和 CSS 使用同一策略；不修改系统设置，不添加用户没有要的开关。发布构建默认仍尊重访问者系统偏好。修复后用与用户相同的媒体条件复测，不能仅再次测试默认无头环境。

逐章写出“进入/滚动发生什么、指针/选择发生什么、对应的公共实现在哪里”。不要求每章无限循环，但不能只有首屏文字入场加全页同一片淡背景。关键内容区应有与内容相关的公开文字/图片/切换表现，不能用装饰小点或重复整块淡入补齐。来源、触发与视觉幅度三项缺一就继续修正。

初始参数只是起点：背景太淡就查渲染和参数，太亮就保护阅读区域，不在“几乎看不见”与“满屏白光”之间二选一。不同组件不要同时控制同一个节点的 transform；让挂载、更新、卸载和离屏暂停有清楚的责任。

## 5. 检查一条跨组件完整路径

从用户操作到实际画面检查，不只测单个按钮。按项目选相关路径，例如：

- 展示页：选择第二件 → 确认可见图片/标题 → 打开详情 → Escape/关闭 → 焦点与画面回到正确位置 → 下一件 → 返回第一件。
- 数据界面：换范围/系列 → 图形变化 → tooltip 精确值 → 关联明细 → 清除选择。数字与图形必须一致。
- 内容工作台：搜索/筛选 → 选择记录 → 展开详情 → 返回 → 筛选和选择状态合理保留。

需要轮播和弹层时，关闭弹层后的焦点恢复可能触发浏览器原生滚动，叠加组件的 translate。出现错位时检查容器 scrollLeft、当前元素位置与组件状态；在合适的非滚动容器使用 overflow:clip，或在关闭后使用 focus({preventScroll:true})，保留原本需要的滚动能力。透明层叠效果也要检查非当前页终态与底面。不要给全站盲加 clip 掩盖布局溢出。

截图或选择器查询可能只读到“正确的当前项”，却漏掉遮在它前面的另一张图。结合实际截图与可见元素位置核对。任何修复完成后复测原来失败的完整操作链。

## 6. 在当前任务内完成修正并收尾

每轮只处理观察到的问题。代表区域阶段优先确认方向和视觉机制成立；整页阶段先修资源缺失/内容错误/交互错位与可读性，再修主题/章节单调和次要装饰。功能修好不代表视觉问题可以略过。把观察写成具体句子，如“白色光带经过标题时无法阅读”，随后改参数或结构，再看相关画面；不要写空泛的“需要更高级”。

收尾必须对照入口的来源覆盖约束：品牌资产、控件及视觉内核中仍有未经要求的自制替代品，应先替换。不能用“整体还不错”“包已安装”或在限制中承认问题来豁免。保留真正必需的布局、主题和业务连接代码，别把“严格复用”误解为不能写整合代码。

达到要求后停止扩张：实际资源已集成、主题表达清楚、主要画面可读、关键操作正确、要求的动效可感知、适用窄屏可用、没有已知阻塞。不要一边留着缺图/叠字一边继续加库，也不要在检查已通过后无理由重测或无限改配色。

完整界面保留简短自检记录：看过的视口/区域、实际执行的操作、自己发现的缺陷与修正、仍未验证的限制。记录观察而非自称“审美满分”；用户对设计的评价仍是最终反馈。没有浏览器等工具时如实说明缺口，不能承诺单轮自动达标。

交付成品入口、打开方式和真实来源。保持预览可用，未经授权不部署到公网或改变系统自启动。不要把这些工程记录堆到产品主界面里。

## 数据交互

# 数据交互：优先完整组件，保持数据语义

## 选什么

| 需求 | 首选方向 | 何时换一种 |
|---|---|---|
| 普通业务图表、tooltip、图例、缩放、状态更新 | ECharts 官方示例 | 已有成熟图表库够用则保持；只需静态小图时无需重型新依赖 |
| 特殊关系图、科学波形、范围刷选与联动 | D3 官方示例与模块 | 数据结构标准、希望少写行为时用 ECharts |
| React 中已有 Recharts 体系 | 沿用现有组件；按实际缺口补齐 | 不为“更高级”无理由重写全部图表 |
| 教学、生成艺术、粒子、可玩信号画布 | p5 | 精确图轴/图例和可访问数据表优先用图表库 |
| 三维产品/空间数据 | Three.js，必要时配对应地图/3D库 | 没有空间含义的数据不要包装成倾斜立体柱图 |

Three.js、p5、D3 不是必须全装的套餐。ECharts 是成熟图表能力，D3 是更灵活的数据与视觉工具；“能画出来”不是它们之间唯一的选择依据。

## 从官方示例开始

- ECharts [示例](https://echarts.apache.org/examples/en/index.html)、[源码](https://github.com/apache/echarts-examples)、[入门](https://echarts.apache.org/handbook/en/get-started/)、[数据过渡](https://echarts.apache.org/handbook/en/how-to/animation/transition/)。先选与数据结构对应的 chart type，再取 option；不要选择最炫图形后强行凑数据。
- D3 [brush](https://d3js.org/d3-brush)、[zoom](https://d3js.org/d3-zoom)、[Focus + Context 示例](https://observablehq.com/@d3/focus-context)。核对示例代码许可；不要混淆库 ISC 与某个历史 gist 的其他许可。

建立数据适配层，使图表直接消费筛选后的真实记录，统计数字、图例、表格和图形来自同一个状态。演示数据可固定种子，标明演示；不能伪造接口成功、企业业绩或科研结果。

## 值得实现的交互

1. 悬停/点击显示单位、日期/对象和精确值，提示不跑出容器。
2. 图例选择更新系列，选中对象联动明细；提供清除/复位。
3. 长序列才需要范围刷选或 dataZoom；只比较四个方法时无需装饰性缩放条。
4. 曲线共用时间/深度轴时用共享游标；纵轴量纲仍分别标注。
5. 键盘或触屏能完成关键选择；悬停不是唯一读取数据的方法。
6. 无数据、请求失败、加载中、数据缺失都是明确状态；不要留空白画布或假数字。

## 保持实例与视觉连续性

ECharts 在有效尺寸的容器初始化一次，更新用 `setOption`，使用稳定的 series/data 身份。在隐藏 Tab/Slide 变为可见后 resize。监听容器尺寸而非仅监听窗口；离开真正销毁实例的视图时 dispose。采用按需导入时，确认 Tooltip、Legend、DataZoom、AxisPointer、Aria 等实际用到的模块已经注册。

D3 使用稳定 key 的数据 join 和 update/exit，而非每次清空 SVG。范围变化时同步轴、路径、提示和摘要，处理 zoom↔brush 相互调用，避免递归更新。统一事件生命周期，移除旧监听。

React 项目要确认 StrictMode 下不会留下双 canvas/双监听。SVG renderer 适合许多轻量图和清晰导出，大数据时根据实测选择 Canvas；不要把一种 renderer 规定为全部项目的答案。

动效是状态变化的可视反馈，不是伪造数据随时间变化。普通同量纲变化可以过渡；切换 SNR、MSE 等不同指标时明确单位和尺度更新，必要时短暂淡入而非把两种量纲形变成同一过程。

## 科研、金额与监控读数

- 精确值标签直接显示最终真实值；不要 CountUp 出一串未发生的中间结果。装饰营销数字是否滚动取决于语义。
- 保留原表、公式、量纲和升降方向。不同单位不能无定义地合成一个总分或雷达面积。
- 只有离散实验点时不插值成平滑连续实验；折线是否连接有明确说明。
- 不随意截断柱图基线制造差距；需要放大差异时用合理点图/明确刻度与精确值。
- 没有原始数据只有论文截图时，做放大、区域指引和出处，不发明数值 tooltip。
- 真实结果、模拟数据、教学示意分别标识；不把一致性检查升级成独立验证，不新增未做的显著性结论。
- 源图保持原色标；不同色标的热图不能直接凭颜色强弱比较。

## 成功的图表区域应同时回答

这是什么指标？范围/单位是什么？哪些元素可以操作？当前选择对应哪批记录？精确值在哪里？差异支持什么结论？没有数据时会怎样？如果只回答“能动”，还没有形成可用的数据界面。

## 产品配方与验收

# 产品配方与验收

以下是组合方法与代表性起点，不是固定模板、硬性依赖清单或额外审批环节。用户的范围、已有框架和风格优先。

## A. 公司官网 / 产品展示站

组合：现有 React 或轻量站点框架 + 一套基础 UI + 一个合适的 React Bits/GSAP 视觉主角 + 真实产品预览 + 按需图表体验。

示例区域映射：

| 区域 | 目的 | 社区起点 | 需要自己完成 |
|---|---|---|---|
| 首屏 | 说清产品和核心价值 | Silk/ColorBends + BlurText/SplitText | 标题、对比度、主视觉比例、主要入口 |
| 项目作品 | 展示具体成果 | Swiper 或适合的图片切换组件 | 真实截图、说明、详情导航、触屏体验 |
| 软件体验 | 让访客真正操作 | 基础组件库 + 图表库 | 本地演示状态、有效交互、诚实的模拟标识 |
| 公司能力 | 帮人理解擅长什么 | 原有列表/Accordion | 信息顺序和具体案例，不写空泛口号 |
| 联系入口 | 到达用户预期动作 | 成熟表单/对话框 | 无后端时说明演示状态，不假装已发送 |

不要用等大白卡展示所有内容，也不必每节一个新特效。可以让作品大图、编辑式条目、数据体验和短段落交替。蓝白是一种可选方向，不是本技能要求所有网站都相同。

## B. 软件平台 / 数据工作台

组合：现有组件体系或 Radix/shadcn/UIkit + 已有图表库或 ECharts + 局部 Motion/Animate UI + Lucide。

优先整理导航、工具栏、内容/辅助区、列表/详情联动和真实媒体缩略图。基于窗口密度确定字号：正文、辅助、标题形成层次，不靠 10px 字和无限缩放塞内容。表格中的空、错、长文本都应处理。

主要动效是选中项移动、详情展开、筛选/加载反馈。不要将地图、视频、绘图叠加层整体倾斜；装饰 canvas 与这些渲染资源竞争时优先保证内容交互。仅做 UI 改版时保留后端、模型和业务事件语义。

## C. 移动网页 / 手机界面原型 / 原生软件

先分清 mobile web、可安装原生应用、手机外框里的图片原型。移动网页沿用当前框架的组件，真实测试触屏、软键盘、底部安全区和弹层。按钮不能只靠 hover 给出状态。

参考 Mobbin 的流程组织，但不是下载其截图当成可点击应用。原生 SwiftUI/Compose/Qt 等优先用平台控件及官方主题，网页经验用于颜色、密度、内容和动作；不把 JSX/CSS 的存在误称为原生实现。

## D. 原生 HTML 单页 / HTML 汇报

普通 HTML 优先 UIkit/语义控件、GSAP、ECharts、Swiper/PhotoSwipe。非必要不迁移 React。使用 JSX 组件需要真实编译/运行环境，不能直接粘进 script 标签。

已有 Reveal.js 汇报优先保留；新项目可按需要选它作为演示框架。根据内容选封面、解释、流程、证据、讨论等版式；完整讲稿与演示内容分别组织，不能删除科研边界。公式交给 KaTeX，流程可用 Mermaid，分步用 Fragments，动画按当前页事件触发。

在 1280×720 等目标投影尺寸检查实际缩放和阅读效果。工具栏挤压画布时，调字号之外还应释放内容区；不要只在设计尺寸下截图。原图放大入口不能替代页内的基本可读性。Auto-Animate 依赖前后可匹配 DOM；render 时清空所有 slide 会破坏预期。

## E. 3D / 创意交互作品

从 Three.js 或 p5 官方最贴近的例子开始，或者按许可使用完整作者项目。普通产品旋转展示用模型、光照、相机和少量交互即可；WASD探索涉及输入、物理、相机、碰撞、触发和资产，不是一个 UI 按钮包能直接解决。

优先取得合适模型/纹理并验证质量。模型制作工具或 MCP 是操作途径，不能保证美术质量。参考图片→模型、模型→绑定动画、场景整合是不同工作。只有二维参考图时不承诺得到一比一真实三维模型。

## F. 离线与跨电脑交付

先确认用户要源码、构建成品、本机预览还是可部署站点。打包体积小不一定内容少；压缩的代码和图片可以很小，但必须实测依赖齐全。

- 保存构建后的 HTML/JS/CSS、字体、图像、模型、许可；开发期 node_modules 通常不需随静态成品分发。
- 断网测试从新会话/清缓存开始，不能把缓存中的 CDN 成功当成离线可用。
- 需要服务器时提供只监听本机的启动器，检查 Node 版本/路径、端口冲突、重复启动和停止；不杀其他服务。
- 用户已有兼容 Node 则复用；不要每次打开页面都安装依赖或启动无关应用。
- macOS shell 文件注意 LF、可执行位和路径含空格；Windows 启动器不能自动视为 Mac 可用。未在真实 Mac 验证就说明该限制。
- 本地地址不能发给另一台电脑直接访问；对方要取得文件并启动，或用户后续授权部署。
- 用户明确要求单文件直接双击时，实际测试 file:// 下所需资源和模块限制；不悄悄替换为必须开发服务器运行的工程。

## 按规模验收

小页面做真实浏览器检查与关键点击即可；复杂工作台/图表改动做有意义的状态回归。不要写一堆只验证 class 名存在的测试来替代视觉观察。

| 检查 | 可观察证据 |
|---|---|
| 实际复用 | 显著标识、产品示意、控件与视觉效果对应真实资产/完整组件；不能只列通用引擎，不留自制临摹替代品 |
| 视觉完成 | 主要内容有层级，文字可读，图片不拉伸，未满屏重复框 |
| 操作完成 | 主按钮、导航、筛选、对话框、复位等执行真实对应动作 |
| 图表 | 图例/选择/精确值/明细一致；空数据明确；单位正确 |
| 动效 | 默认运行且不擅自显示全局开关；主要章节有可感知的文字/影像/交互表现，反复进入无叠加，系统减少动效可用 |
| 多尺寸 | 宽屏、小窗口、适用窄屏无遮挡和意外横向溢出 |
| 资源 | 图像/字体/WebGL无缺失；冷启动离线按要求可运行 |
| 稳定性 | 控制台无相关异常；反复切换不残留计时器/canvas |
| 交付 | 源码/成品、打开方式、来源与未验证项清楚 |

无浏览器时可检查构建和源码，但明确尚未做视觉/交互实测。最后回复用户时重点给结果和打开方式，附简短的真实资源说明，不把工程细节塞进产品界面。

## 用于检查技能是否做出合理选择的场景

以下是自查案例，不是已经执行过的跨模型实验：

1. “原生单文件HTML，不要React”：应选原生兼容资源，测试单文件方式，不能复制 JSX。
2. “已有Vue后台，只美化”：保留栈与业务，优先现有库/原生库，不改后端。
3. “蓝白官网，多一点动效”：保留蓝白但改变内容节奏，丰富状态反馈，不能满屏球池。
4. “精确实验数据要有动态”：使用真实数据更新/选择，不滚动出虚构读数。
5. “没有网络，已有node_modules”：检查缓存可用组件，标明来源核查限制，不谎称新下载成功。
6. “发给有Node的Mac离线观看”：构建资源与启动器完整，验证限于实际测试过的平台。
7. “我想做原生Android软件”：按原生控件实现，网页库只作为风格/交互参考。
